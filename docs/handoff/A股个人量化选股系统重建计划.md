# A股个人量化选股系统重建计划
## Summary
本项目调整为“资金中性”的个人 A 股量化选股与交易辅助网站。系统核心不再围绕固定账户资金、资金池或仓位分配展开，而是专注于从全市场筛选出最值得关注、最适合短线与波动周期交易的股票，并提供大盘、板块、个股、新闻财报、回测和持仓观察信息。实际买入金额、仓位比例、加减仓幅度由你人工决定。
当前执行原则：
- 权威配置只认 `src/quant_trading/config.py`，但资金配置只作为可选显示信息，不参与选股优先级。
- 数据源主线只认 Tushare Pro + PostgreSQL。
- 不模拟资金流，不伪造数据，不用静态股票池替代全市场。
- 先跑通真实链路，再扩展因子、回测和前端体验。
- 研究层与生产 baseline 分开，所有实验保留版本记录。
- 40% 年化作为个人目标背景，不作为系统承诺，也不作为选股硬过滤条件。
- 系统输出“股票优先级、理由、风险、适用交易风格”，不输出强制仓位方案。
## Phase 0: 口径收口与系统体检
目标：把项目从“历史文档混杂状态”收口到可持续开发状态，并移除固定资金分配对系统主流程的影响。
实施内容：
- 明确当前系统定位为“选股与交易辅助”，不是资金分配器。
- 保留 `src/quant_trading/config.py` 为唯一运行时配置入口。
- 将资金字段降级为可选参数：
- 可以用于页面展示或回测初始资金。
- 不用于过滤候选股。
- 不用于自动生成买入金额。
- 将 `config/portfolio_config.py`、`config/strategy_config.py`、`config/dual_strategy_config.py` 等历史配置明确标注为 historical/reference，不再作为运行口径。
- 将 `docs` 分为当前执行文档、研究文档、历史归档三类；旧完成报告不得再作为实现依据。
- 跑当前健康检查，形成真实断点清单：
- `pytest`
- `python scripts/run_system_readiness.py`
- `python scripts/run_factor_validation.py readiness`
- `python scripts/run_ml_lab.py readiness`
交付物：
- 当前项目地图。
- 配置口径说明。
- 健康检查报告。
- 第一批必须修复的错误清单。
验收标准：
- 当前文档明确说明：系统只负责筛选股票和辅助判断，不负责决定资金分配。
- 没有页面或文档继续把固定资金结构作为主流程。
- 测试失败项被分类为：环境缺失、真实 bug、历史测试过期、数据缺失。

- 个股资金流 `moneyflow`
- 交易日历

- 数据同步必须记录每次任务状态、时间窗口、写入行数、失败原因。

交付物：

- 不存在核心服务内置测试股票池或 mock 资金流。
## Phase 2: 大盘与板块分析主链路
目标：把你的核心分析顺序固化为系统主流程：先看市场，再看板块，再看个股。
实施内容：
- 大盘分析维度：
- 指数趋势：上证、深证、创业板。
- 市场广度：上涨家数、下跌家数、涨跌比。
- 成交活跃度：成交额、量能变化。
- 情绪风险：涨停、跌停、连板、炸板相关指标，能拿到真实数据才启用。
- 波动风险：指数波动率、短期回撤。
- 输出市场信号：
- `green`: 市场环境支持积极交易。
- `yellow`: 市场环境一般，精选个股。
- `red`: 系统性风险高，候选股应降级为观察。
- 板块分析维度：
- 申万行业短中期强度。
- 行业指数 5 日、10 日、20 日涨跌幅。
- 板块成交量变化。
- 板块相对大盘强弱。
- 板块内强势股集中度。
- 概念板块先做预留接口，不在第一版强行接入不稳定数据源。
- 市场与板块结果必须写入数据库或报告，供选股、回测和前端复用。
交付物：
- `/api/market` 稳定输出。
- `/api/sectors` 稳定输出。
- 市场红绿灯。
- 强势板块 TopN 与弱势板块 BottomN。
- 板块结果缓存，避免反复打 Tushare。
验收标准：
- 任意选股结果都能追溯到当日市场环境和板块环境。
- 市场红灯状态下，系统不会输出“强买入”类措辞，只输出观察或谨慎标签。
- 板块强度不是固定值，不允许所有股票得到同一板块分。
## Phase 3: 全市场选股主流程
目标：形成可解释、可回测、可人工复核的候选股生成流程。
实施内容：
- 股票池来源：
- 每次从数据库中的 Tushare 全市场股票池读取。
- 排除 ST、退市整理、停牌、上市天数过短、流动性不足标的。
- 策略分两条：
- `short_term_core`: 短线核心候选，偏波动周期、趋势延续、确定性更高。
- `aggressive`: 进攻候选，偏强势、短周期、弹性和情绪。
- 评分维度：
- 技术强度。
- 资金流。
- 板块强度。
- 市场适配。
- 估值。
- 成长。
- 质量。
- 选股流程：
- 全市场预筛。
- 因子评分。
- 市场环境修正。
- 板块强度修正。
- 风险标签生成。
- 输出 Top 候选。
- 每个候选股必须给出：
- 总分。
- 分项得分。
- 所属行业/板块。
- 主要入选原因。
- 主要风险标签。
- 适合交易风格。
- 建议观察价位。
- 止损参考。
- 目标持有周期。
- 不根据账户资金过滤股票：
- 不因为一手金额高而剔除。
- 可以展示一手金额作为参考。
- 不输出建议买入金额或建议仓位。
交付物：
- `/api/selection/run`
- `/api/selection/runs`
- `/api/selection/runs/<id>`
- 选股结果导出 CSV。
- Web 端候选股列表。
验收标准：
- 选股结果可解释，不只是一个分数。
- 候选股能追溯到原始行情、资金流、板块和市场环境。
- 短线核心和进攻策略使用同一数据底座，但权重和风险阈值不同。
- 当关键数据缺失时，系统降低置信度或标记缺失，不直接补中性分伪装完整。
- 候选股排序不依赖账户资金规模。
## Phase 4: 持仓观察与交易纪律
目标：网站能记录你当前真实持仓，并给出风险与操作倾向，但不决定资金分配。
实施内容：
- 持仓录入方式：
- CSV 导入。
- Web 手动添加。
- 后续预留券商导出文件适配。
- 持仓字段：
- 股票代码、名称、策略类型、买入价、数量、买入日期、当前价、最高价、最低价、备注。
- 持仓分析不输出目标仓位，只输出：
- 当前盈亏。
- 持仓天数。
- 趋势状态。
- 资金流状态。
- 板块状态。
- 风险标签。
- 操作倾向：观察、持有、减弱、退出关注、强风险。
- 风控规则：
- 单票止损。
- 时间止损。
- 动态止盈。
- 板块转弱退出。
- 大盘系统性风险提醒。
- 所有建议只输出为人工操作卡片，不自动下单，不给强制仓位。
交付物：
- `/api/positions`
- `/api/positions/summary`
- `/api/positions/import_csv`
- `/api/positions/update_prices`
- `/api/trades`
- 持仓观察工作台。
- 今日风险与操作倾向卡片。
验收标准：
- 系统能识别持仓风险，但不替你决定资金比例。
- 每个退出、减弱、持有、观察建议都有触发原因。
- 风控提示优先级高于新候选股提示。
- 不出现“系统自动执行交易”的行为。
- 不输出固定买入金额、加仓金额或减仓比例。
## Phase 5: 回测系统升级
目标：让策略先经过可信回测，再进入实盘观察。
实施内容：
- 回测必须纳入 A 股交易约束：
- T+1。
- 涨跌停无法成交。
- 停牌。
- 手续费。
- 滑点。
- 买入卖出按下一交易日可成交价格模拟，不能默认信号日收盘价成交。
- 100 股整数倍交易。
- 回测类型：
- 单股买入持有基准。
- 规则选股 TopN 轮动。
- ML Top10 组合回测。
- 短线核心与进攻候选分别回测。
- 回测资金只作为模拟参数：
- 默认值可以保留，但不作为主系统口径。
- 用户可以每次回测手动输入。
- 回测结果重点看排序有效性、胜率、回撤和交易质量。
- 指标：
- 总收益。
- 年化收益。
- 最大回撤。
- 夏普比率。
- 胜率。
- 盈亏比。
- 平均持仓天数。
- 换手率。
- 最大连续亏损。
- TopN 命中率。
- 回测结果必须保存，不覆盖历史实验。
交付物：
- `/api/backtest/buy_hold` 保留。
- 新增组合回测服务。
- 回测结果表。
- 回测报告页面。
- 实验版本记录。
验收标准：
- 任意策略参数变更都会生成新实验记录。
- 回测报告能明确显示交易约束和费用假设。
- 不能只用收益率判断策略，必须同时看回撤和交易次数。
- 回测资金可配置，不再写死为固定账户资金。
- 回测需要证明“选股排序有效”，不只是证明某个资金曲线好看。
## Phase 6: Factor Lab 与 ML Lab 研究闭环
目标：让因子和机器学习服务于验证和排序，不直接绕过风险控制。
实施内容：
- 保留当前 Factor Lab：
- 构建因子快照。
- 构建 forward returns。
- 计算 Rank IC、ICIR、TopN 收益、分组单调性。
- Walk-forward 验证。
- 保留当前 ML Lab：
- 训练稳定/进攻双评分。
- 生成 Top10。
- 生成执行包。
- 记录模型版本。
- 因子治理：
- 不因单次失败删除因子。
- 因子状态分为 `candidate`、`observe`、`usable`、`rejected`。
- 每次模型训练绑定因子池版本。
- ML 输出只能进入候选排序与解释，不直接给出“必买”。
交付物：
- Factor readiness 页面。
- ML readiness 页面。
- 因子验证报告页面。
- ML Top10 页面。
- 模型版本与实验台账。
验收标准：
- 可以解释某只股票进入 Top10 的主要贡献因子。
- 模型输出与规则风控冲突时，风控优先。
- 所有模型和因子结果都可追溯到训练窗口和数据版本。
- ML Top10 不按账户资金过滤，只按评分、风险和市场适配排序。
## Phase 7: 新闻、公告与财报人工复核
目标：把非结构化信息变成买入前的证据面板，而不是直接自动交易。
实施内容：
- 财报复核：
- ROE、营收增速、扣非净利润增速、毛利率、资产负债率。
- 最近报告期变化趋势。
- 异常风险：利润下滑、高商誉、高负债、经营现金流异常。
- 新闻公告复核：
- 先做链接与摘要面板。
- 标记利好、利空、中性、待确认。
- 人工确认后再进入交易计划。
- AI/DeepSeek：
- 当前阶段默认关闭。
- 只在数据管线稳定后作为摘要助手启用。
- AI 结论必须显示来源文本，不作为唯一决策依据。
交付物：
- 个股详情页。
- 财报摘要面板。
- 新闻公告证据面板。
- 人工复核标签。
- 复盘日志关联。
验收标准：
- 每只最终候选股都有“量化理由 + 基本面/新闻复核状态”。
- 没有来源的新闻不进入评分。
- AI 摘要不能直接改变交易建议，只能作为人工参考。
## Phase 8: Web 工作台
目标：建设真正可日常使用的个人选股与交易辅助网站。
技术路线：
- 第一版沿用 Flask + Jinja + 原生 JavaScript，避免在后端口径未稳定时引入大型前端重构。
- 页面以工作台为第一屏，不做营销式首页。
- 后续 API 稳定后，再考虑 React/Vue 重构。
页面结构：
- 总览工作台：
- 数据状态。
- 市场红绿灯。
- 强势板块。
- 今日短线核心候选。
- 今日进攻候选。
- 当前持仓风险。
- 今日观察与风控卡片。
- 选股页：
- 策略选择。
- 运行选股。
- 结果排序。
- 分项得分。
- 一手金额参考。
- 入选原因。
- 风险标签。
- 导出。
- 持仓页：
- 持仓列表。
- 盈亏。
- 风险标签。
- 操作倾向。
- 复盘入口。
- 回测页：
- 参数选择。
- 回测运行。
- 收益曲线。
- 指标表。
- 交易明细。
- 研究页：
- Factor Lab。
- ML Lab。
- 实验记录。
- 复盘页：
- 每日复盘。
- 个股笔记。
- 交易后评价。
验收标准：
- 每个页面都能显示加载、成功、失败、空数据状态。
- 所有交易提示必须带原因。
- 页面不展示历史过期术语，例如旧版 `baseline_v0`、固定 `70/30` 或固定账户总资金。
- 页面不展示“建议买入金额”“目标仓位”作为系统结论。
## Phase 9: 实时监控与预警
目标：先做“提醒”，不做自动交易。
实施内容：
- 盘前：
- 数据同步状态检查。
- 昨日强势板块。
- 今日观察池。
- 盘中：
- 当前持仓价格更新。
- 止损/止盈预警。
- 大盘急跌预警。
- 板块明显转弱预警。
- 盘后：
- 选股运行。
- 回测/复盘。
- 持仓风险报告。
- 预警渠道第一版只做 Web 页面和日志；后续再扩展邮件、企业微信或钉钉。
交付物：
- 预警规则配置。
- 预警日志表。
- Web 预警面板。
- 盘前/盘中/盘后命令入口。
验收标准：
- 预警不会直接执行交易。
- 每条预警都有触发数据和时间。
- 重复预警有去重机制，避免刷屏。
## Phase 10: 部署与安全
目标：本地优先，必要时再对外访问。
实施内容：
- 本地运行：
- Windows 本机。
- PostgreSQL 本地或局域网。
- Flask 本地端口。
- 对外访问前必须增加：
- 登录认证。
- 强密码。
- Secret key 环境变量。
- 禁止 debug 暴露公网。
- HTTPS 或可信内网穿透。
- 不在仓库中提交 `.env`、token、数据库密码。
交付物：
- 本地运行手册。
- 可选公网访问方案。
- 安全检查清单。
验收标准：
- 真实 token 和密码不出现在文档或代码。
- 远程访问必须登录。
- 生产运行不启用 Flask debug。

数据与环境测试：
- 无 `.env` 时，配置错误必须清晰。
- 无 `TUSHARE_TOKEN` 时，真实数据测试跳过或返回配置错误。
- 无 `DB_PASSWORD` 时，数据库功能不得假装成功。
- 数据同步失败必须记录失败 run。
选股测试：
- 未知 `strategy_type` 必须报错。
- `short_term_core` 和 `aggressive` 使用不同策略标签。
- 选股结果必须包含分项得分和风险标签。
- 资金流缺失时不能生成假资金流评分。
- 候选股排序不依赖账户资金。
持仓测试：
- CSV 导入字段校验。
- 数量必须为 100 股整数倍。
- 持仓估值、盈亏、风险标签计算正确。
- 市场红灯时进攻候选应降级或标记风险。
回测测试：
- 手续费和滑点生效。
- T+1 规则生效。
- 涨跌停不可成交逻辑生效。
- 停牌或缺价格时跳过并记录原因。
- 同一参数重复运行可追溯。
- 回测初始资金可配置。
前端测试：
- 首页不显示历史错误口径。
- 页面不把固定资金当作主配置。
- API 失败时前端显示错误状态。
- 空数据时不显示误导性结果。
## Operating Workflow
每日盘前：
- 检查数据状态。
- 查看市场红绿灯。
- 查看昨日强势板块与今日观察池。
- 确认是否适合交易。
盘中：
- 只监控持仓风险和候选股触发条件。
- 红灯或急跌时优先处理风控。
- 资金决策由你人工决定。
盘后：
- 同步当日数据。
- 运行大盘与板块分析。
- 运行选股。
- 更新持仓价格。
- 记录复盘。
- 必要时运行回测或因子验证。
周度：
- 汇总候选股表现。
- 复核候选股命中率和交易执行偏差。
- 记录哪些因子或板块判断有效。
月度：
- 评估是否接近个人收益目标。
- 检查最大回撤是否超过个人承受范围。
- 决定是否调整参数，调整必须先进入回测和观察期。
## Assumptions
- 资金规模变化较大，系统不以固定账户总资金作为主逻辑。
- 交易市场只覆盖 A 股，不做港股、美股。
- 当前阶段不自动下单，只做个人交易辅助。
- 第一版网站继续使用 Flask，不引入 React/Vue 重构。
- Tushare Pro 是主数据源；其他数据源后续只作为补充。
- DeepSeek/AI 分析默认关闭，等数据链路稳定后再启用。
- 历史文档保留但不作为执行依据。
- 所有交易结论都必须允许人工复核。
- 资金分配、买入金额、加减仓比例由你人工决定。
