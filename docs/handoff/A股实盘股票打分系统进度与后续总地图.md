## Summary
当前系统定位已经明确：资金中性的 A 股全市场选股与交易辅助系统。系统不决定仓位、不决定买入金额，只负责真实数据获取、因子计算、模型评分、候选排序、风险提示、回测验证和人工复核支持。
当前已完成：数据底座、基础 Web 工作台、Factor Lab、ML Lab 初版、研究训练包、GPU 实验准备工具。
下一阶段重点：在 GPU 上跑全量 ML baseline，审查 `stable` 与 `aggressive` 两套评分是否有真实排序能力，然后决定是否升级特征、调参和上线评分版本。

## 后续流程总地图
### Phase A：GPU 全量 baseline
目标：判断当前特征体系是否已经有可用排序能力。
推荐 GPU：
- 首选：`A800 40G`
- 备选：`RTX 4090 48G`
- 5090 32G：便宜很多时可选，否则不优先
- 不建议：A100 64G / A800 80G，当前过剩
实验规模：
- 交易日：581
- fold：23
- 模型：3 个
- 目标：2 个
- 总训练：138 次
- 预计耗时：A800 40G 上约 2-5 小时，保守 1 天足够
你要做：
- 租 GPU。
- 把我指定的文件上传。
- 按我给你的命令执行。
我来做：
- 检查环境。
- 指导上传。
- 指导运行。
- 读结果。
- 判断模型是否可用。
- 决定下一轮实验怎么改。
### Phase B：GPU 结果审查
目标：判断 `stable` 和 `aggressive` 是否值得进入下一轮。
审查重点：
- `stable`
- Top10/Top20 是否正收益
- 多 fold 是否稳定
- 回撤是否低
- 弱市是否抗跌
- Top10/20/50 是否一致
- `aggressive`
- Top10 收益/回撤比
- 强势窗口弹性
- 弱势窗口亏损控制
- Top10 好但 Top20/50 差时是否标记高风险
可能结论：
- `usable`：可进入下一轮模型定型。
- `observe`：有价值但需要特征或参数改进。
- `rejected`：当前特征/标签不足，不能上线。
### Phase C：特征工程 v2
如果 baseline 不够强，进入特征增强。
要补的特征方向：
- 1/3/5/10/20/60 日收益。
- 5/10/20 日量能变化。
- 资金流 3/5/10 日累计。
- 个股相对行业强度。
- 行业内排名。
- 距离近期高低点。
- 波动率变化。
- 量价背离。
- 有金融意义的交叉项。
目标：从当前约 18 个特征扩到 50-150 个。
### Phase D：模型实验 v2
在特征 v2 后再跑：
- LightGBM
- XGBoost
- CatBoost
- 不同目标标签
- 不同 TopN
- 不同训练窗口
- 小规模超参搜索
这时才考虑更复杂模型。
当前不急着上深度表格模型。
### Phase E：评分系统定型
当某个模型组合通过验证后，形成：
- `stable_v1`
- `aggressive_v1`
定型内容：
- 模型文件。
- 特征列表。
- 训练数据版本。
- 参数。
- 验证报告。
- 风险标签规则。
- 适用市场环境。
- 不适用市场环境。
上线前仍然不自动交易，只进入网站候选排序和人工复核。
### Phase F：实盘观察期
上线后先观察，不直接信任。
观察内容：
- 每日 Top10 后续表现。
- 命中率。
- 回撤。
- 与实际手动交易偏差。
- 板块环境是否影响模型。
- 哪些因子贡献有效。
- 哪些风险标签真的有用。
观察至少 2-4 周，再决定是否作为主评分系统。
### Phase G：生产工作台增强
模型稳定后，再回到前端：
- 显示 stable/aggressive 评分。
- 显示贡献因子。
- 显示模型版本。
- 显示训练窗口。
- 显示风险标签。
- 显示 TopN 历史表现。
- 显示候选股后续跟踪。
现在前端先够用，不急着继续美化。
